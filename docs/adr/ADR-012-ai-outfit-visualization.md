# ADR-012: AI Outfit Visualization

## Status

Accepted.

## Context

Closet AI needs an approximate visual preview of an already valid outfit. The
preview can be slow or fail independently and must not become authoritative
wardrobe state.

## Decision

An `OutfitVisualization` is a private, derived artifact linked to a persisted
`Outfit`. The authoritative composition remains `Outfit` plus its garment IDs.

Generation is on demand. The API persists a `PENDING` visualization and enqueues
only its ID in BullMQ. The existing worker calls
`GenerateOutfitVisualizationUseCase`, which loads the outfit, garment metadata,
and available original garment images through ports. OpenAI is accessed through
`OutfitVisualizationPort`; generated bytes are stored through
`ObjectStoragePort` and the record becomes `READY` only after storage succeeds.

The v1 presentation uses a neutral mannequin or generic full-body figure. It is
not virtual try-on and never uses a user's face, body image, or measurements.
Garments without an image are represented from their persisted metadata and are
reported to the provider as lacking a visual reference.

Visualizations use the private object-key layout:

```text
users/{userId}/outfits/{outfitId}/visualizations/{visualizationId}.webp
```

Generation failures set the visualization to `FAILED` and never invalidate or
modify the outfit. A `READY` visualization is reused; explicit regeneration is
deferred.

## Alternatives Considered

- Synchronous generation: rejected because image latency should not hold an HTTP request open.
- Automatic generation for every recommendation: rejected because it multiplies cost for artifacts the user may never view.
- Virtual try-on or user likeness: rejected as outside the MVP and materially more sensitive.
- Additional image providers: rejected to preserve the approved single-provider MVP.

## Consequences

- PostgreSQL stores status and metadata, not image bytes.
- Redis/BullMQ remains operational infrastructure; jobs are retry-safe by visualization ID.
- Flutter polls a bounded number of times and keeps the textual outfit usable on failure.
- Generated visualizations are regenerable derivatives and need not be included in authoritative backups.

## Risks

- The generated image may not preserve every garment detail or exact fit.
- Provider image generation has variable latency and cost.
- Multiple original references may still produce imperfect composition.
